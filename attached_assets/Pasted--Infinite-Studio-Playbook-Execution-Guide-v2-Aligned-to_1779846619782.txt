# Infinite Studio: Playbook Execution Guide v2
### Aligned to the 6-Phase Production Pipeline

This guide details the exact 3-phase AI prompt sequence that powers the **Screenwriting Playbook** (Phases 1–3). Phases 4–6 are handled by the Higgsfield REST API and are documented separately at the end. Follow this pipeline step-by-step. All prompts match the exact `server.ts` endpoints.

---

> **Model Note:** All Gemini calls use `gemini-2.0-flash`. The string `gemini-3.5-flash` in older versions of `server.ts` does not exist — update to `gemini-2.0-flash` or `gemini-2.5-pro` in your Replit Secrets if you have access.

## ── PHASE 1 (Screen 01): DISCOVERY ──
**Endpoint:** `POST /api/generate-phase1`  
**Objective:** Establish world boundaries, dialectical argument, and generate modular, production-ready Character Sheets that unify narrative depth with precise style-locking, kinetic, and audio API telemetry. Outputs 3–4 story directions for the user to choose from.

```
We are starting PHASE 1: THE COSMOLOGY & THE DIGITAL ACTORS of our short film pipeline.

Analyze the following premise:
"[USER PREMISE HERE]"

Generate THREE distinct narrative directions for this setup. For each option, output a raw, well-structured JSON array matching this exact structural schema:
```

## ── PHASE 3 (Screen 03): SCREENPLAY ──
**Endpoint:** `POST /api/generate-phase3`  
**Objective:** Translate the complete, locked Phase 2 JSON blueprint into a professional, production-ready screenplay with deep subtext, integrating kinetic vocabulary and dynamic vocal stress cues into the script page.

> **Correction from original guide:** The copy-paste prompt in the original guide incorrectly labelled this phase as "PHASE 5". The correct label is **PHASE 3: THE SCRIPT EXECUTION**.

### Phase 3 Input:
Pass the full Phase 2 blueprint JSON as `blueprint` in the request body.

### Execution Laws (passed as system instructions):

1. **FORMAT:** Standard screenplay layout. CHARACTER NAMES in uppercase at dialogue headings and action line introductions. Parentheticals denote active vocal stress states — never literal physical actions.

2. **DIALOGUE SUBTEXT CONSTRAINT:** Every spoken line acts as a diplomatic surface mask. Dialogue must naturally deliver the psychological agendas mapped in the `subtextual_beat_progression` gerund tags. Characters never speak inner truths until the Story Climax.

3. **KINETIC PHYSICALITY:** Weave each character's kinetic profile (`posture`, `gait`, `gesture_vocabulary`, `reaction_tempo`) directly into action blocks. Replace dry exposition with physical somatic gestures.

4. **VOCAL STATE PARENTHETICALS:** Translate `vocal_state` from beats into precise parentheticals using the exact `stress_cues` text (e.g., `(voice cracking under strain, shallow rapid exhalations)`).

5. **FRENCH SCENES:** Advance internal rhythm every time a character enters, exits, or radically alters power dynamics.

6. **VARIATION:** Alternate rapid visual action blocks with expansive, emotionally dense subtextual confrontations.

7. **THEMATIC TRANSITIONS:** Link consecutive scenes using a sensory hinge — a shared object, opposing light quality, sound bridge, or word contrast.

8. **VISUAL FLORA:** Include `visual_flora` color shifts (e.g., violet, pale lavender, defensive crimson) in action blocks to represent characters' biochemical stress states.

### Phase 3 Output:
Plain text screenplay in standard Hollywood format. No JSON wrapper. The script begins immediately on the first line.

## ── PHASE 4 (Screen 04): VISUAL ASSET GENERATION ──
**Endpoint:** `POST /api/generate-visual`  
**Powered by:** Higgsfield REST API  
**Objective:** Generate the complete visual asset library before any shot generation — characters, locations, and props — using data already present in the Phase 1 JSON.

### Three Asset Tabs:

**Characters Tab**
- One sub-tab per cast member
- Pulls `prompts.master_visual_reference.master_grid_prompt` directly from Phase 1 JSON
- Appends `--ar 16:9` to every grid prompt before sending to Higgsfield
- Passes `visuals.negative_prompt` as the `negative_prompt` parameter
- Returns a single wide 16:9 image — render in one wide container, not a grid of cells
- Caption below: `Row 1: Full-body poses (5 angles)` / `Row 2: Headshots (5 expressions)`
- Approve button increments the asset counter
- "Add State Variant" button generates a second grid when the character's arc transitions

**Locations Tab**
- One card per unique `setting_macro` value across all sequences
- Prompt built from `setting_macro` + `visualDesc` + style preset from Phase 2

**Props Tab**
- One card per item in `meaning.props_sheet`
- Prompt built from `name` + `description` of each prop

### Higgsfield API Call Structure:
```typescript
POST https://api.higgsfield.ai/v1/image/generate
Headers:
  Authorization: Bearer ${HIGGSFIELD_API_KEY}
  X-Secret: ${HIGGSFIELD_SECRET}
Body:
{
  prompt: character.prompts.master_visual_reference.master_grid_prompt,
  negative_prompt: character.visuals.negative_prompt,
  model: "soul",
  aspect_ratio: "16:9"
}
```

Poll `GET /api/job-status/:jobId` every 3 seconds until status = `completed` or `failed`.

## ── PHASE 5 (Screen 05): SHOT GENERATION ──
**Endpoint:** `POST /api/generate-shot`  
**Powered by:** Higgsfield Seedance 2.0  
**Objective:** Convert each scene's shot list into storyboard images, then promote approved images to video clips.

### Shot ID System:
Each shot maps to a beat using the convention: `A{act}_Q{sequence}_S{scene}_B{beat}`  
Example: `A1_Q1_S1_B1` = Act 1, Sequence 1, Scene 1, Beat 1

> **Generation unit is the SHOT, not the beat.** Beats inform the motion description inside a shot prompt. Each video clip corresponds to a camera setup (`setting_micro` field). A single shot may contain 2–3 beats worth of action.

### Seedance 2.0 Prompt Format:
Build prompts using this exact structure from Phase 2 beat data:

```
[SHOT SETUP] {setting_micro framing}, {character.cinematics.framing}, {character.cinematics.lighting}
[OPENING FRAME] {beat.action physical description — focal target and body state}
[MOTION] {char_id}: {beat.action gerund} — {kinetics.gesture_vocabulary detail}
[CLOSING FRAME] {beat.reaction physical description — closing body state of responding character}
[ATMOSPHERE] {beat.visual_flora} | Vocal state: {beat.vocal_state}
```

### Generation Flow:
1. "Generate Image" → single image render via Higgsfield Soul or Nano Banana 2
2. Image approved → "Promote to Video" → Seedance 2.0 video generation
3. Video approved → shot marked complete (green dot in shot list)
4. All shots complete → "Proceed to Assembly →" CTA unlocks

### Character State Selector:
For each shot, display a selector: `Baseline` or `Post-Arc (State 2)` per character. This determines which character grid variant was used as the reference for that generation.

## ── PHASE 6 (Screen 06): ASSEMBLY & EXPORT ──
**Endpoint:** Uses Higgsfield Canvas + ElevenLabs  
**Objective:** Arrange approved video clips into a final cut with character audio and virality scoring.

### Assembly Components:

**Timeline**
- Horizontal drag-to-reorder strip of all approved video clips
- Each clip labelled with shot ID and opening beat text snippet
- Click a clip to view its beat reference, character state, and flora/environment context

**ElevenLabs Audio Panel** (per selected clip)
- Pulls `audio.voice_identity.voice_clone_id` and the active `vocal_state` telemetry for that beat
- Stability, similarity_boost, and style_exaggeration values fed directly from character's `state_telemetry` JSON
- Requires `ELEVENLABS_API_KEY` in Replit Secrets

**Virality Predictor**
- Calls Higgsfield Virality Predictor tool (MCP or REST equivalent)
- Scores: Emotional Impact, Visual Novelty, Pacing Score
- Displays overall engagement score (0–100) with one-line recommendation

**Export**
- "Export Final Cut" button → downloads assembled video
- Commercial rights granted on Studio plan tier only
