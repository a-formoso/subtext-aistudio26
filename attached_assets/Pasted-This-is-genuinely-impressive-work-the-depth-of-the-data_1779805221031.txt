### The Core UI Problem To Fix First

The current UI has three issues bleeding across all screens:

1. **The JSON sidebar is always visible.** It should be collapsed by default, accessible via a small "Dev / Data" toggle for power users only.
2. **Too many competing panels.** Greenhouse telemetry, beat IDs, vocal sliders, style palettes — all fighting for attention simultaneously. Each screen should have one primary content area and one action.
3. **No clear sense of progress.** The phase numbers (01, 02, 03) exist but feel decorative. Users need to feel forward momentum.

**Fix:** Add a persistent top progress bar showing phases 1–6 with the current phase highlighted. Collapse the right sidebar by default. Each screen gets a single primary panel and a single primary CTA button.

### New Phase 5 — Shot Generation (Higgsfield Seedance 2.0)

**Purpose:** Turn each scene's shot list into storyboard images, then promote to short video clips.

**New backend endpoint needed:** `POST /api/generate-shot`

Takes a shot's composition data (`framing`, `lens`, `key_light`, `kinetic_token`, `visual_flora`) and formats it into a Seedance 2.0 prompt using this structure:
```
[SHOT SETUP] {framing}, {lens}, {key_light}
[OPENING FRAME] {focal_target description}
[MOTION] {kinetic_token} — {motion field from beat}
[CLOSING FRAME] {closing value state description}
[ATMOSPHERE] {visual_flora color + env_vfx}
```

**Screen layout:**
- Left: shot list for current scene (pulled from existing shot manifest in Phase 2/3 data)
- Right: selected shot panel showing:
  - Auto-generated Seedance prompt (editable)
  - "Generate image" button → shows result inline
  - "Promote to video" button → calls video generation
  - Character state selector (baseline vs post-arc-change variants from Phase 4)
- Generation happens per shot, not all at once
- Single CTA when all shots are approved: "Proceed to assembly →"

**Important:** Generation is per-shot not per-beat. Beats inform the motion description inside a shot prompt, but each video clip corresponds to a camera setup (the `setting_micro` field already defines this).
